# Add a new book to Yomimasu

When the user attaches a book (one or more `.txt`  or .json files, or pasted Japanese text) and asks to add it, run the full pipeline below. Do NOT ask the user any questions (except the anchor confirmation in step 6 if the book gets split) — infer everything via Lovable AI Gateway.

Single-chapter books only. If user explicitly mentions chapters, tell them this skill doesn't handle multi-chapter and stop.
Audio is never generated by this skill.

## Inputs

The user attaches up to 3 text files (or pastes text). Detect which difficulties are provided:

- 1 file → treat as `original`. Generate `simplified` + `intermediate` with AI.
- 2 files → ask the user which is which only if filenames are ambiguous; otherwise infer from filenames (`simplified`, `intermediate`, `original`).
- 3 files → use as-is.

Filename hints: `simple/easy/s` → simplified; `inter/medium/m/i` → intermediate; `orig/full/o` → original.

## Steps (run in order)

### 1. Pick a book id

- Romaji, lowercase, hyphenated (e.g. `kokoro`, `botchan`, `yuki-onna`).
- Must be unique across `src/data/books/` and `src/data/books.ts`.

### 2. Generate missing difficulty versions (if needed)

Use the `ai-gateway` skill. Model: `google/gemini-2.5-pro`.

Prompt template for `simplified` (from original):

> Rewrite this Japanese text for JLPT N4 learners: simpler kanji, short sentences, common grammar. Preserve the story, characters, and key imagery. Output Japanese only, no explanations, no furigana, no parens.

Prompt template for `intermediate` (from original):

> Rewrite this Japanese text for JLPT N3 learners: moderate kanji, natural sentence length, common modern grammar. Preserve the story, characters, imagery, and tone. Output Japanese only, no explanations, no furigana, no parens.

Strip ALL furigana (`漢字（かんじ）` → `漢字`), Aozora markers (`《》`, `｜`, `［＃...］`), and parenthetical notes from the original before saving.

### 3. AI-deduce metadata

One Lovable AI call (Gemini 2.5 Pro) with the original text, returning JSON:

```json
{
  "titleJp": "...",
  "titleEn": "...",
  "author": "...",
  "genre": "fiction|folk-tales|sci-fi|slice-of-life|horror",
  "jlptLevel": "N5|N4|N3|N2|N1",
  "coverColor": "#RRGGBB",
  "readingTimeMin": 10,
  "synopsis": "..."
}
```

JLPT scale: N5 easiest, N1 hardest. Be honest — most classical literature is N1/N2.

### 4. Create `src/data/books/<id>.ts`

Three exports, matching the project convention:

```ts
// <titleJp> — <author>
export const <id_camel>Simplified = `...`;
export const <id_camel>Intermediate = `...`;
export const <id_camel>Original = `...`;
```

Use camelCase for variable names (e.g. `yukiOnna`, `botchan`).

### 5. Register in `src/data/books.ts`

- Add the import line at the top alongside other book imports.
- Append a new entry to the `books` array (follow the existing single-chapter pattern — see `sakura` or `urashima`).

### 6. Auto-split into parts (conditional)

Measure `originalText.length` (the unsplit blob).

- **If `< 2500` chars** → SKIP this step entirely. Leave the book as a single blob. Continue to step 7.
- **If `≥ 2500` chars** → apply the `split-book-into-parts` skill in full on this book:
  - Target segments of **1300–1700 chars** in the `original`, cut only on narrative ruptures (paragraph break + sentence terminator `。！？」`).
  - Write **anchors** in Title Case, 2–5 words, evocative, **no spoilers** (no verbs revealing outcomes).
  - Align `intermediate` and `simplified` part-by-part on the SAME narrative beats. All three difficulties end up with the same number of parts.
  - Self-check before writing: concat of each version's parts (joined by `'\n\n'`) is byte-identical to the original blob from step 4; every part ends on `。｜！｜？｜」`; counts match across difficulties and anchors.
  - Rewrite `src/data/books/<id>.ts` with `…SimplifiedParts`, `…IntermediateParts`, `…OriginalParts`, `…Anchors` exports + back-compat aliases (`<id>Simplified = <id>SimplifiedParts.join('\n\n')` etc.).
  - Extend the entry in `src/data/books.ts` with `parts: {...}` and `anchors: [...]`, and add the new exports to the import line. Leave `content` in place.
  - **Stop and confirm the anchors with the user** before running step 8 (grammar costs API calls).

Refer to `skill/split-book-into-parts` for the full rules — this step is a direct invocation of it.

### 7. Run the tokenizer

```bash
npx tsx scripts/generate-tokens.ts
```

Regenerates `src/data/book-tokens/books/<id>.ts` and `word-counts.ts`. Verify the new file exists.

If the user later reports wrong readings, add entries to `src/data/book-reading-overrides.ts` under the book id, then re-run the tokenizer.

### 8. Generate grammar notes

- **If the book was split in step 6** → copy `scripts/generate-grammar-for-lemon.ts` (per-part shape).
- **Otherwise** → copy `scripts/generate-grammar-for-sakura.ts` (single-blob shape).

Copy to `scripts/generate-grammar-for-<id>.ts`. Replace every reference to the source book id (`lemon` or `sakura`) with `<id>` — imports, variable names, the `allGrammar['<id>']` key.

```bash
npx tsx scripts/generate-grammar-for-<id>.ts
```

Verify in `src/data/book-grammar.ts`: for a split book, `bookGrammar['<id>']['simplified'].length === N` (number of parts).

### 9. Preload dictionary entries

```bash
npx tsx scripts/sync-dictionary-to-db.ts
```

Requires `SUPABASE_SERVICE_ROLE_KEY` in env (already a secret — fetch with `secrets--fetch_secrets` and pass as env var when running).
Idempotent: scans all books' tokens, finds entries missing from `dictionary`, batch-fetches them from Jisho via the `jisho-lookup` edge function.

### 10. Preload sentence translations

```bash
npx tsx scripts/preload-translations.ts --book <id>
```

- Splits every sentence in all 3 difficulties (parts included if the book was split), hashes them SHA-256, bulk-checks `sentence_translations`, and batches the missing ones through the `translate-sentences-batch` edge function.
- Idempotent: already-cached sentences are skipped. One-shot cost; the Reader's 🌐 toggle is then instant for every reader.
- The `--book <id>` flag scopes the work to only the new book.

### 11. Verify

- The build runs automatically — check it succeeds.
- If split: visit `/reader/<id>/simplified/part-1`, confirm prev/next pills work, BookDetail lists the anchors, GrammarPanel on `part-2` shows only part-2 notes.
- Confirm with the user: book id, title, JLPT, whether split (and how many parts), and that tokens + grammar + dictionary + translations are populated.

## Notes

- The `book-tokens` file powers furigana, dictionary popup, and flashcards. Step 7 is non-optional.
- Step 9 makes WordPopup load instantly (no Jisho round-trip on first tap). It catches conjugated forms via `b` (base form) tokens.
- Step 10 makes the per-sentence English translation overlay instant — without it, the first reader of each sentence waits for a live AI call.
- Never edit `src/integrations/supabase/types.ts`, `client.ts`, or auto-generated token files by hand.
- Cover colors already in use: avoid duplicates by glancing at the existing books array.
